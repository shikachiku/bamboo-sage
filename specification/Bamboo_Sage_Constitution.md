1. 開発理念

Bamboo Sage は、
長期運用できる個人専用トレード支援システムである。

設計思想は

・シンプル
・保守しやすい
・長期間運用できる

を最優先とする。

コードより設計を優先する。

2. 運用環境

開発環境

・Chromebook
・Linux (Penguin)
・Python
・VSCode

を標準環境とする。

Windowsでも動作できる設計を目指す。

3. 費用

基本方針

月額費用 0 円

有料クラウドサービスを前提に設計しない。

必要になった場合のみ、
クラウド対応を追加する。

4. データ管理

RAWデータは資産である。

RAWデータは削除しない。

RAWデータから

・上位足
・平均足
・インジケータ

をいつでも再生成できる構造にする。

インジケータは保存しない。

毎回計算する。

5. 時間足

取得

・60分足
・日足

初回のみ

可能な限り

・4時間足
・週足
・月足

もダウンロードする。

通常運用では

60分足

↓

4時間足生成

日足

↓

週足生成

↓

月足生成

とする。

6. NYクローズ

日足は

UTC-4

NYクローズ基準

を採用する。

夜間も含めた日足を使用する。

7. Live / Closed

通常運用

Live

バックテスト

Closed

とする。

実運用では
Liveのみ使用する。

8. バックテスト

バックテストは

日足

週足

月足

のみで行う。

4時間足は

実運用専用

とする。

バックテストは

売買ルールの優位性

を検証するために使用する。

4時間足は

エントリータイミング改善

のみを目的とする。

9. 銘柄数

システムは

50〜100銘柄

運用を前提として設計する。

銘柄情報は

config

で一元管理する。

コード内へ銘柄名を書かない。

10. データ保存

プログラムは

GitHub

で管理する。

運用データは

Google Drive

で管理する。

保存対象は

・RAWデータ

・Liveデータ

・Closedデータ

・ログ

などとする。

GitHubには大量の運用データを保存しない。

データは

data/

以下へ保存する。

11. フォルダ構成

bamboo-sage/

config/

data/

download/

engine/

indicators/

strategy/

logs/

specification/

12. パス

ソースコード内へ

データ保存先を直接記述しない。

データ保存先は

config

で一元管理する。

すべてのプログラムは

設定ファイルから保存先を取得する。

保存先は

Google Drive

ローカルフォルダ

外部ストレージ

などへ変更できる構造とする。

保存先を変更する場合は

設定ファイルのみ変更すればよい設計とする。

DOWNLOAD_HISTORY.py で採用した

データアクセス方式を

Bamboo Sage の標準方式とする。

新規プログラムは

この方式で開発する。

既存プログラムは

順次この方式へ統一する。

13. 移行

新しいPCでは

GitHubからプログラムを取得し

Google Driveを同期し

requirements.txt

でPython環境を構築するだけで

動作できる構造を目指す。

14. コーディング方針

関数は

1つの役割だけを持つ。

コードは短く、

読みやすくする。

コメントは

理由を書く。

処理内容だけを書かない。

15. 開発ルール

新しい機能を追加する前に

この憲法を確認する。

設計変更が必要なら

Versionを更新する。

コードより

憲法を優先する。

既存プログラムを修正する場合は

Bamboo Sage の標準構造へ

順次統一する。

実装前には

憲法との整合性を確認する。

16. Bamboo Sage の目的

Bamboo Sage は

売買システムではない。

投資判断支援システムである。

最終判断は

必ず人間が行う。
